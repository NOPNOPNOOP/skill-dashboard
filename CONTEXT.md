# Domain Context & Ubiquitous Language (`CONTEXT.md`)

## Domain Glossary

- **Canonical Skill (`CanonicalSkill`)**: A unique physical skill folder on disk, keyed by its resolved `realpath`. Even if symlinked into 5 different agent folders (`.claude/skills`, `.pi/agent/skills`, `.openclaw/skills`, etc.), it is represented as a single `CanonicalSkill` entity.
- **Agent Mount (`AgentMount`)**: A binding between a `CanonicalSkill` and a specific agent ecosystem directory (`claude`, `claude-workspace`, `codex`, `codex-system`, `opencode`, `pi-agent`, `pi`, `openclaw`, `continue`, `trae`, `agents-hub`). Tracks whether the mount is a valid symlink, a standalone directory, or a `broken_symlink`.
- **Lock Provenance (`LockProvenance`)**: Package origin metadata extracted from `~/.agents/.skill-lock.json` (v3) or `~/skills-lock.json` (v1), recording `source`, `sourceType`, `sourceUrl`, `skillFolderHash`, and `updatedAt`.
- **4-Layer Config Cascade (`ConfigCascade`)**: The deterministic configuration merging pipeline that produces a skill's effective `SkillManifest`:
  1. **Layer 0 (`ZeroConfigHeuristic`)**: Automatic introspection of `SKILL.md` frontmatter, markdown headings, bash codeblock CLI synopses (inferring typed form fields), relative reference doc links (`references/**/*.md`), directory file trees, and Codex `agents/openai.yaml`.
  2. **Layer 1 (`CompanionManifest`)**: Skill-embedded configuration at `<canonical_path>/.dashboard/manifest.yaml` (or `.json`) with companion `assets/` and `docs/`.
  3. **Layer 2 (`GlobalOverride`)**: User-level override at `~/.config/skill-dashboard/overrides/<unit_id>/manifest.yaml` (with backward-compatible fallback to `~/.claude/skill-dashboard/configs/<skill_id>/manifest.yaml`).
  4. **Layer 3 (`WorkspaceOverride`)**: Active workspace override at `<active_workspace>/.claude/skill-dashboard/configs/<skill_id>/manifest.yaml`.
- **Action Group (`ActionGroup`) & Action (`ActionItem`)**: Logical grouping of executable operations within a skill. Each `ActionItem` defines a command template, optional typed `FormField[]` schema, `danger` level (`safe` | `warn` | `danger`), `interactive` TUI flag, and `defaultRunner` (`web_terminal` | `external_terminal` | `copy_command` | `copy_agent_prompt`).
- **Active Workspace (`ActiveWorkspace`)**: The currently targeted project working directory (e.g. a VSIP backend git worktree) used to resolve `{{project_root}}`, `{{python}}` (auto-detecting `<workspace>/.venv/bin/python` or `uv run python`), and workspace-scoped overrides.
- **Human-Approval Gate (`HumanApprovalGate`)**: Safety confirmation workflow in the UI for `warn` and `danger` actions that, once explicitly approved by the human user in the browser, injects required flags (such as `--human-approved`) or unlocks execution.
- **Execution Run (`ExecutionRun`)**: A single invocation of an `ActionItem` managed by a native Bun bidirectional PTY (`Bun.spawn({ terminal })`) where `pid === pgid === sid` (session leader), enabling clean process-group termination (`kill(-pid)`) and full-screen interactive TUIs (`prompt_toolkit`, `fzf`).
- **Multi-Tier Run Persistence (`MultiTierPersistence`)**:
  - **Tier 1 (`HotRingBuffer`)**: In-memory ring buffer per active run for zero-latency WebSocket broadcast.
  - **Tier 2 (`AppendLogStream`)**: Append-only raw ANSI byte stream persisted at `~/.local/share/skill-dashboard/logs/<run_id>.log`.
  - **Tier 3 (`RunMetadataIndex`)**: Embedded `bun:sqlite` table (`runs`) at `~/.local/share/skill-dashboard/dashboard.db` indexing run lifecycle (`running`, `completed`, `failed`, `cancelled`, `interrupted`), exit codes, timestamps, masked parameters, and detected output artifacts.
- **Session Re-Attach (`SessionReAttach`)**: The protocol whereby a browser client connecting to `/ws/runs/:runId` first replays historical ANSI bytes from Tier 2 from a requested byte offset and seamlessly transitions into live Tier 1 streaming (including alternate-screen-buffer `\x1b[?1049l` sanitization on unexpected exit).
- **Reactive Context (`ContextField`)**: Skill-wide reactive state variables (e.g., `target_env: local | uat | prod`) rendered in the top context toolbar. Modifying a context variable automatically invalidates and recomputes all dependent `DataNode`s in topological order and interpolates `{{context.<key>}}` across commands and scripts.
- **Polyglot Data Node (`DataNode` & `DataSnapshot`)**: The unified reactive compute primitive declared in `manifest.yaml` under `data:`. Executes in `zsh`, `ts` (in-memory `Bun.Transpiler` TypeScript), `python` (workspace `.venv/bin/python` with `def main(ctx)` structured return), `sqlite` (native `bun:sqlite`), `glob`, `file`, or `passive` (populated by `ActionItem.output.intoData`), parses stdout via `DataParser` (`json`, `jsonl`, `whitespace-table`, `regex`, `csv`, `tsv`, `kv`, `lines`, `raw`), runs optional `DataTransform` (`ts` / `python`), and normalizes output into canonical `DataShape`s (`scalar`, `kv`, `list`, `table`, `matrix`, `stream`, `raw`).
- **Reactive Graph Engine (`ReactiveGraphEngine`)**: The backend execution and dependency scheduler that extracts implicit (`{{context.*}}`, `{{data.*}}`, `ctx.data[*]`) and explicit (`dependsOn`) DAG edges, performs Single-Flight deduplication and TTL caching, watches local directories via debounced `fs.watch` (`watchFiles`), invalidates nodes on `ActionItem` completion (`invalidateOnActions`), and pipes `ActionItem.output.intoData` back into the graph.
- **Custom HTML App View & Bridge 2.0 (`window.SkillDashboard`)**: The iframe host and injected RPC/DOM bridge serving custom `.html` views under `/skill-app/:skillId/*`, supporting both zero-JS declarative widget mounting (`<div data-sd-widget="id">`, `<div data-sd-context-bar>`, `<button data-sd-action="id">`) and programmatic subscriptions (`SkillDashboard.subscribe(nodeId, cb)`, `SkillDashboard.data(nodeId)`, `SkillDashboard.setContext(key, val)`).
- **TypeScript Prelude (`prelude`)**: Explicit opt-in boolean flag on `DataNode` and `DataTransform` (`prelude: false` by default for standard pure TypeScript scope with top-level `import` rewriting; when `prelude: true` is explicitly declared as recommended in `SKILL.md`, pre-injects `{ fs, path, os, Database, YAML, $ }` in an outer closure scope so local variables can safely shadow them).
- **Explicit Modular Manifest (`ModularManifest` & `SymbolProvenance`)**: The two-phase linking architecture in `.dashboard/manifest.yaml` using explicit top-level `includes: string[]`, array-item `- $include: "<path>"`, and reusable `defs` + `$ref: "#/defs/<key>"`. Tracks `SymbolProvenance` (the exact relative module file defining each `context`, `data`, `action`, and `view`) and preserves per-module file editing in the UI without flattening.
- **Manifest Symbol & Diagnostics CLI (`manifest-cli`)**: The companion CLI tool (`map`, `refs`, `validate`, `eval-data`, `split`, `bundle`, `schema`, `inspect`, `init`, `folder`, `scratchpad`, `wait`) that maps cross-file bidirectional symbol references (including `.html` views), performs 3-tier validation (Zod schema + cross-file reference/cycle checking + TS/Python syntax & `prelude` pre-flight), evaluates data nodes in the terminal, splits monolithic manifests into domain modules, inspects arbitrary folders for Agent-driven `.dashboard` generation, manages `ManagedFolder` and `AgentScratchpad` lifecycles, and blocks on `UnitEvent` HITL feedback.
- **XDG 3-Tier Storage Governance (`DashboardPaths`)**: Clean separation of configuration, persistent data, and ephemeral cache/scratchpads:
  1. **Config Tier (`~/.config/skill-dashboard/`)**: Declarative human-editable `config.yaml` (storing `managedFolders`, `watchRoots`, and `preferences.unconfiguredFolderAction: "ask" | "agent" | "skeleton" | "raw"`) and `overrides/<unit_id>/manifest.yaml` (Layer 2 `GlobalOverride`).
  2. **Data Tier (`~/.local/share/skill-dashboard/`)**: Embedded SQLite `dashboard.db` (`runs`, `settings`, `unit_events`), raw ANSI `logs/<run_id>.log`, per-unit persistent sandbox `units/<unit_id>/` (exposed as `{{data_dir}}` and `$SD_DATA_DIR`), and per-run generated artifacts `artifacts/<unit_id>/<run_id>/` with a `latest` symlink (exposed as `{{artifacts_dir}}` and `$SD_ARTIFACTS_DIR`).
  3. **Cache & Scratchpad Tier (`~/.cache/skill-dashboard/`)**: Project-scoped ephemeral Agent consoles `scratchpads/<project_slug>/<pad_id>/`, per-unit disposable cache `units/<unit_id>/` (exposed as `{{cache_dir}}` and `$SD_CACHE_DIR`), isolated multi-line script files `runtime/scripts/sd-script-<run_id>.sh`, and `runtime/daemon.log`.
- **Managed Unit & Unit Kind (`unitKind: "skill" | "workspace" | "scratchpad"`)**: The generalized entity managed by the Studio. Every unit shares the full Reactive Graph, 4-Layer Cascade, Web PTY, and Custom HTML View engine, categorized into three top-level sidebar sections:
  1. **Agent Scratchpad (`scratchpad`)**: Ephemeral interactive console or HITL approval board created on-the-fly by an AI Agent under `~/.cache/skill-dashboard/scratchpads/<project_slug>/<pad_id>/`, automatically inheriting the originating project's `defaultWorkspace` (`{{project_root}}` & `{{python}}`), reachable via deep link (`/?id=<unit_id>`), and supporting one-click **Promotion (`Promote`)** into either the project's `<project_root>/.dashboard/` or a global skill (`~/.agents/skills/<id>`).
  2. **Managed Workspace / Folder (`workspace`)**: Any local repository or directory explicitly registered in `config.yaml` (`managedFolders`) or discovered via shallow `watchRoots`. When added without an existing `.dashboard/manifest.yaml`, triggers the configurable `unconfiguredFolderAction` workflow (`ask` modal with "Remember my choice / Don't ask again" checkbox) to let an Agent generate `.dashboard/` via `manifest-cli inspect/init/validate`, initialize a minimal skeleton, or mount as a raw folder.
  3. **Canonical Skill (`skill`)**: Cross-agent skill discovered across Claude Code, Codex, OpenCode, Pi, OpenClaw, and `~/.agents/skills`.
- **3-Channel Run Artifact Pipeline (`RunArtifact` & `ArtifactMatcher`)**: Deterministic post-run artifact extraction and whitelisted preview/download gateway (`/api/runs/:runId/artifacts/:index`), merging three prioritized channels without lower-priority overwrites:
  1. **Channel 1 (Explicit YAML `ActionItem.artifacts` Rules)**: Supports interpolated path templates (`path: "{{form.out}}"`) and ANSI-stripped regex stdout extractors (`fromStdout: "Saved to (?<path>\\S+\\.html)"` verified with `mtimeMs >= run.startedAt - 1000`), custom `label`, `kind` (`html` | `file` | `json` | `image` | `markdown`), and `onComplete` behavior (`badge` | `open` | `download`).
  2. **Channel 2 (Stdout Protocol Marker)**: Zero-config extraction of `::artifact path=<path> [label="..."]` lines emitted by scripts.
  3. **Channel 3 (`{{artifacts_dir}}` Directory Scan)**: Automatic collection of any files written into the run's dedicated `$SD_ARTIFACTS_DIR` directory during execution.
- **HITL Unit Event & Synchronous Agent Wait (`UnitEvent` & `manifest-cli wait`)**: Bidirectional Human-in-the-Loop synchronization table (`unit_events` in `dashboard.db`) and Bridge API (`SkillDashboard.submitDecision(payload)` / `POST /api/skills/:id/decision`). Allows a CLI Agent running `manifest-cli wait <unit_id> [--since <seq_or_ts>]` to block with zero race conditions and immediately receive structured JSON when the user completes an action or submits an approval/selection in the browser.
- **Zero-Config Multi-Line Bash Statement Aggregator (`splitBashBlockIntoStatements`)**: The lexical statement aggregator in Layer 0 (`ZeroConfigHeuristic`) that merges backslash line continuations (`\`), multi-line unclosed single/double-quoted blocks (e.g. `curl ... -d '{ ... }'`), and heredocs (`<<EOF ... EOF`) into cohesive single or multi-line `ActionItem`s instead of splitting a multi-line command into broken per-line fragments.
- **Targeted Agent Fix Drawer & Click-to-Context (`AgentFixDrawer` & `AgentFixTarget`)**: The non-modal bottom-right floating drawer in the Studio UI that lets the user summon an AI Agent (`claude` or `codex` in the Web PTY, or copy the assembled prompt) with custom repair/authoring instructions and pinned UI targets (`action-group`, `action`, `data-node`, `context`, `view`) captured by clicking elements directly on the page (`data-sd-pick-kind` / `Alt+Click`). Automatically resolves the write target to the existing defining module/layer file (`SymbolProvenance` / existing override / existing companion) or defaults to creating `<skill_dir>/.dashboard/manifest.yaml`.
- **Progressive Skill Reference Architecture (`ProgressiveSkillReferences`)**: The `npx skills`-compatible hierarchical organization of `skill-dashboard` itself (`SKILL.md` entry point + modular `references/01..04-*.md` deep-dive manuals + `package.json` `bin` entries + portable `~/.agents/skills/skill-dashboard/...` paths), giving AI Agents complete, progressive specifications for authoring manifests, polyglot data graphs, Bridge 2.0 HTML views, and HITL scratchpads.
